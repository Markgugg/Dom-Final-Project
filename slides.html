SCRIPTOR

A Programming Language Written Like a Movie

CS 420 — Programming Languages  |  Spring 2026

"Every valid Scriptor program reads like a short film."

What Is Scriptor?

  • Name: Latin for writer — specifically a screenwriter. Programs are scripts; files use the .scp extension.
  • Purpose: A general-purpose interpreted language where all syntax mirrors Hollywood screenplay format.
  • Core idea: Variables are characters, functions are scenes, loops are montages, conditionals are meanwhile cuts.
  • Goal: Make programming feel narrative and approachable — every program tells a story.
  • Stack: Pure Python 3.8+, zero external dependencies. Run with python3 interpreter.py <file.scp>

Language Philosophy

"The compiler is the audience."

  • Code should be readable as prose, not just syntactically valid.
  • Every programming construct maps to a cinematic concept — nothing is arbitrary.
  • The language forces narrative structure: setup (OPENING CREDITS), action (DIRECTOR'S CUT), resolution (FADE OUT).
  • Beginner-friendly: no semicolons, no curly braces, no import boilerplate — just write the story.

Why I Created It

  • Most languages are designed around machine efficiency or mathematical formalism — not human storytelling.
  • Screenplay format is one of the most universally understood structured writing forms in the world.
  • Wanted to explore: can syntax itself carry meaning beyond its logic?
  • Inspired by natural-language languages (Inform 7, COBOL) but with a cinematic twist instead of plain English.
  • Result: programs that are simultaneously valid code and readable narrative.

Language Style & Design

Structural Rules

  • Every program opens with SCRIPT: Title
  • Entry point is always DIRECTOR'S CUT
  • Program ends with FADE OUT.
  • Indentation defines scope — no braces needed
  • Multi-word keywords (CUT TO, OPENING CREDITS) read as natural phrases
program skeleton
SCRIPT: My Film

OPENING CREDITS
  CHARACTER title AS NARRATOR = "Scene One"

SCENE: OpeningAct
  title SAYS LINE

DIRECTOR'S CUT
  CUT TO OpeningAct
FADE OUT.

Program 1 — Hello World

hello_world.scp
SCRIPT: Hello World

DIRECTOR'S CUT
  CHARACTER lead AS NARRATOR = "Hello World!"
  lead SAYS LINE
FADE OUT.

How It Works

  • SCRIPT: declares the program title — like a film slate.
  • DIRECTOR'S CUT is the entry point — execution starts here.
  • CHARACTER lead AS NARRATOR declares a string variable named lead.
  • lead SAYS LINE — the character speaks their value. Prints lead: "Hello World!"
  • FADE OUT. ends the program.

Program 2 — Simple Math

math.scp
SCRIPT: Simple Math

DIRECTOR'S CUT
  CHARACTER a AS HERO = 10
  CHARACTER b AS HERO = 5
  CHARACTER total AS HERO = a + b
  CHARACTER diff  AS HERO = a - b
  SAYS "Sum:"
  total SAYS LINE
  SAYS "Difference:"
  diff SAYS LINE
FADE OUT.

How It Works

  • HERO is the numeric type — integers and floats both use this role.
  • Arithmetic expressions (a + b, a - b) are evaluated at declaration time.
  • SAYS "Sum:" is a bare print — no variable attached, just a string literal.
  • total SAYS LINE prints the variable with its name label: total: "15"
  • Supports + - * / % and comparisons == != < > <= >=

Program 3 — Personal Greeting

greeting.scp
SCRIPT: Personal Greeting

SCENE: Greet (CAST: name AS NARRATOR)
  SAYS "Welcome to the show,"
  name SAYS LINE

DIRECTOR'S CUT
  CHARACTER guest AS NARRATOR = "Alice"
  CUT TO Greet(guest)
FADE OUT.

How It Works

  • SCENE: Greet defines a reusable function named Greet.
  • CAST: name AS NARRATOR — the scene takes one string parameter. Actors are cast in a role.
  • CUT TO Greet(guest) — calls the scene with guest as the argument. A film cut to jumps to a new scene.
  • Scene variables are local — name only exists inside Greet.

Program 4 — The Countdown

countdown.scp
SCRIPT: The Countdown

OPENING CREDITS
  CHARACTER count AS HERO = 10

SCENE: Launch Sequence
  MONTAGE count FROM 10 TO 1
    SAYS count
  END MONTAGE
  SHOUTS "We have liftoff!"

DIRECTOR'S CUT
  CUT TO Launch Sequence
FADE OUT.

How It Works

  • OPENING CREDITS is global scope — sets the stage before any scene runs.
  • MONTAGE count FROM 10 TO 1 — a for loop that auto-decrements. A film montage compresses many moments into one sequence.
  • END MONTAGE closes the loop block.
  • SHOUTS writes to stderr with emphasis. Output is wrapped: !! We have liftoff! !!

Program 5 — The Audition

audition.scp
SCRIPT: The Audition

SCENE: Audition (CAST: score AS HERO)
  MEANWHILE score >= 80
    SAYS "You got the part."
  OTHERWISE
    SAYS "Better luck next time."

DIRECTOR'S CUT
  CHARACTER applicant AS HERO = 92
  CUT TO Audition(applicant)
FADE OUT.

How It Works

  • MEANWHILE score >= 80 — an if statement. "Meanwhile" in film shows a conditional parallel reality.
  • OTHERWISE — the else branch. Like cutting to the alternate outcome.
  • Indentation defines which statements belong to each branch — no braces or end markers.
  • With applicant = 92, the condition is true → prints "You got the part."

Program 6 — FizzBuzz

fizzbuzz.scp
SCRIPT: FizzBuzz

OPENING CREDITS
  CHARACTER limit AS HERO = 30

SCENE: CheckFizzBuzz (CAST: n AS HERO)
  CHARACTER rem3 AS HERO = n % 3
  CHARACTER rem5 AS HERO = n % 5
  MEANWHILE rem3 == 0
    MEANWHILE rem5 == 0
      SAYS "FizzBuzz"
    OTHERWISE
      SAYS "Fizz"
  OTHERWISE
    MEANWHILE rem5 == 0
      SAYS "Buzz"
    OTHERWISE
      SAYS n

DIRECTOR'S CUT
  MONTAGE i FROM 1 TO limit
    CUT TO CheckFizzBuzz(i)
  END MONTAGE
FADE OUT.

How It Works

  • Uses nested MEANWHILE/OTHERWISE to handle all three cases: divisible by both, by 3, by 5.
  • n % 3 and n % 5 are stored as local HERO variables for clarity.
  • The MONTAGE calls CheckFizzBuzz for each i from 1 to 30 — 30 scene calls in one montage.
  • Demonstrates: modulo, nested conditionals, loop + scene call, global variable as loop bound.

Complex Program — The Grand Cinema Report

What It Does

  • Processes 5 film screenings and generates a full box-office report.
  • Calculates gross revenue per screening and assigns a 4-tier verdict.
  • Tracks the highest-grossing screening using global state accumulation.
  • Wraps each screening in PLOT TWIST error handling.
  • Prints a final summary with total revenue and sequel greenlight verdict.

Features Used

  • Multiple interdependent scenes with RETURN values
  • Global state mutated across scene calls
  • 3-tier nested MEANWHILE/OTHERWISE
  • PLOT TWIST (try/catch) wrapping scene calls
cinema_report.scp — scene structure
SCENE: CalcRevenue   ← returns tickets * price
SCENE: GetVerdict   ← 4-tier verdict check
SCENE: TrackHighest ← updates global max
SCENE: ReportScreening
  ← calls all 3 above, updates globals
SCENE: SafeScreening
  PLOT TWIST
    CUT TO ReportScreening(...)
  OTHERWISE
    SAYS "[ERROR] Screening failed"

DIRECTOR'S CUT
  CUT TO SafeScreening(1, 320, 18)
  CUT TO SafeScreening(2, 510, 15)
  CUT TO SafeScreening(3, 95,  22)
  CUT TO SafeScreening(4, 640, 14)
  CUT TO SafeScreening(5, 210, 20)

Interpreter Architecture

Lexer

tokenize()

Regex-based. Handles multi-word keywords like CUT TO, DIRECTOR'S CUT. Produces a flat token stream.

→

Parser

Parser class

Recursive descent. Builds an AST. Handles expressions, nested blocks, scenes, loops, and conditionals.

→

Interpreter

Interpreter class

Tree-walking executor. Two-level scope: local → global. RETURN implemented via ReturnSignal exception.

interpreter.py
 ├── tokenize()           Lexer
 ├── Parser               parse_program / parse_scene / parse_block / parse_statement / parse_expr
 └── Interpreter          _eval() / _exec() / _call_scene() / _resolve()
